# График ПВЗ — Telegram Mini App + Supabase

Project ref: `gwkurcwggttztchmhvzy` (уже подставлен во все SQL и настройки ниже).

## Структура

```
pvz-app/
  sql/
    schema.sql            — базовые таблицы + RLS (для НОВОЙ установки)
    setup_extra.sql        — все функции/триггеры/cron поверх schema.sql (для НОВОЙ установки)
    migration_*.sql        — история отдельных шагов (уже применены, для справки)
  supabase/functions/
    telegram-auth/          — вход через Telegram, выдача JWT
    bot-webhook/             — обрабатывает /start в боте
    send-reminders/          — напоминания о сменах (cron, каждые 5 мин)
    send-file/                — доставка CSV-экспортов в Telegram (обход блокировки скачивания)
    notify-event/              — уведомления о новых/решённых заявках
    send-monthly-report/        — автоотчёт админам за 3 дня до очистки
  web/
    index.html, css/styles.css, js/config.js, js/api.js, js/app.js
```

## Установка с нуля (если разворачиваешь на новом проекте Supabase)

1. Создать проект Supabase, включить расширения **pg_cron** и **pg_net** (Database → Extensions).
2. SQL Editor → выполнить `sql/schema.sql`, затем `sql/setup_extra.sql`.
3. Создать бота через @BotFather, получить токен.
4. Supabase CLI: `supabase link --project-ref <ваш-ref>`, затем секреты:
   ```
   supabase secrets set BOT_TOKEN=<токен_бота>
   supabase secrets set WEBAPP_URL=<ссылка на web/, например GitHub Pages>
   supabase secrets set APP_JWT_SECRET=<JWT Secret из Project Settings → JWT Keys>
   ```
5. Задеплоить все функции:
   ```
   supabase functions deploy telegram-auth --no-verify-jwt
   supabase functions deploy bot-webhook --no-verify-jwt
   supabase functions deploy send-reminders --no-verify-jwt
   supabase functions deploy send-file --no-verify-jwt
   supabase functions deploy notify-event --no-verify-jwt
   supabase functions deploy send-monthly-report --no-verify-jwt
   ```
6. Установить вебхук бота (в браузере):
   ```
   https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=https://<ref>.functions.supabase.co/bot-webhook
   ```
7. Заполнить `web/js/config.js` реальными `SUPABASE_URL`, `SUPABASE_ANON_KEY` (Publishable key), `AUTH_FUNCTION_URL`, `SEND_FILE_FUNCTION_URL`.
8. Выложить папку `web/` на GitHub Pages (или другой статический хостинг).
9. Открыть бота, нажать /start → «Открыть график» — создастся ваша запись в `employees` (`is_active=false`). В Table Editor вручную поставить себе `is_active=true` и `is_admin=true`.

Если проект уже развёрнут (как у тебя сейчас) — все эти шаги уже сделаны, `setup_extra.sql` можно не запускать (там дубли `migration_*.sql`, которые ты применял по шагам, — тоже смысла перезапускать нет).

## Как это работает

- Сотрудник открывает бота → кнопка открывает `web/index.html` внутри Telegram.
- Фронтенд шлёт `Telegram.WebApp.initData` в `telegram-auth`, та проверяет подпись, находит/создаёт сотрудника, выдаёт JWT.
- Все данные — через Supabase (PostgREST) с этим JWT, Row Level Security сама решает, что можно смотреть/менять обычному сотруднику, а что только админу.
- Оплата смены считается **не по сотруднику, а по ПВЗ + времени начала**: полная смена / вечерняя / промежуточная почасовая — плюс можно вручную задать точную сумму на конкретную смену.
- Заявки на смены идут в очередь (видно, кто и когда откликнулся), можно предложить своё время, админ принимает как есть / с изменением времени / отклоняет.
- Экспорт данных (ведомости, история сотрудника, отчёты) приходит **документом от бота в Telegram**, а не через скачивание в браузере — это обходит ограничения Telegram WebView.
- 15 числа каждого месяца автоматически удаляются смены/бонусы/штрафы за прошлые месяцы; за 3 дня до этого (12 числа) админам сам приходит CSV-отчёт; уволенные сотрудники полностью удаляются через 7 дней.

## Реализованные функции

**Все:**
- Календарь по ПВЗ, разделённый на WB/OZON, с несколькими сотрудниками в ячейке дня
- Отклик на свободную смену (целиком или с предложенным временем)
- Вкладка "Смены" со своим листанием месяца, профиль с доходом за месяц
- Тёмная/светлая тема, чат с коллегой в один клик

**Админ:**
- Назначение/редактирование смен с поиском сотрудника и ручной корректировкой суммы
- Очередь откликов на смену: принять как есть / с другим временем / отклонить / отклонить все разом
- Массовое создание свободных смен на месяц вперёд одной кнопкой
- Тарифы по каждому ПВЗ (полная / вечерняя / промежуточная ставки, пороговый час, время открытия/закрытия)
- Бонусы/штрафы, сводная ведомость, детальный экспорт смен, экспорт истории сотрудника
- Блок "Сегодня работают" — сводка по всем ПВЗ без пролистывания
- Раздел "Новые / ожидают доступа" отдельно от активных сотрудников
- Полное управление ПВЗ (добавить/удалить/тарифы)

## Известные ограничения (не критично, но на будущее)

- Сотрудник пока не может сам отказаться от уже подтверждённой смены через приложение — только через админа.
- Нет проверки на пересечение смен одного человека в разных ПВЗ по времени.
- Обмен сменами между сотрудниками напрямую (без одобрения каждого шага админом) не реализован.
